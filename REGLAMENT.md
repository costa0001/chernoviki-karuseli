# Регламент: как делать и публиковать карусели для @bravo.konstantin

Версия от 05.11.2026. Документ полностью описывает рабочий процесс, чтобы новый чат мог продолжить работу без повторных объяснений. Перенесите этот PDF в новый чат и начните со стартового промпта из раздела 16.

## 1. Коротко о процессе

1. Найти тему: новость, вирусная карусель другого автора или идея Константина.
2. Собрать смыслы, проверить факты (новости только через веб-поиск, с источниками).
3. Написать план слайдов (8–10, иногда до 15).
4. Подготовить ОДНО фото на обложку из фото-базы (или иллюстрацию, если фото не подходит по смыслу).
5. Сверстать слайды кодом (HTML/CSS → Playwright → PNG → JPG), используя модуль tools/gendesign.py из репозитория.
6. Посмотреть контакт-лист всех слайдов глазами.
7. Сохранить JPG и подпись в GitHub-репозиторий, сделать push.
8. Написать подпись 1300–1900 знаков с кодовым словом 3 раза.
9. Запланировать в Metricool (Instagram, тип POST) по raw-ссылкам GitHub.
10. Отчитаться коротко: что сделано, когда выйдет, прислать контакт-лист.

Постоянное указание Константина: **«Не спрашивать и не тормозить процесс»**. Решения принимать самостоятельно, а спорные моменты коротко отметить в отчёте.

- Обращение на **«вы»**.
- **Никаких длинных тире** (—). Вместо них точка, двоеточие или запятая. Короткие предложения.
- Валюта **евро**. Исключение: исторические факты Константина, которые изначально в долларах (150 млн $, 50 000 $, акции по 1 $).
- **Никаких выдуманных цифр, результатов, отзывов, кейсов и фактов о Константине.** Если факта нет в списке ниже, не писать. Нельзя «я начал с цели», «я сомневался» и т. п., если он этого не говорил.
- Чужие смыслы пересказывать своими словами, не копировать текст дословно.
- Хорошо работает добавление смысла для 40+: «ваш опыт это преимущество, а не помеха».
- Новости: только проверенные через веб-поиск, указывать даты и суммы как в источниках. Если пример не совсем подходит под формулировку (например, Кипр 2013 это не хакеры, а решение властей), писать честно.

## 5. Структура карусели

Типовой вариант на 9 слайдов:

1. **Обложка**: одно фото Константина сверху (760 px) + заголовок 72–76 px заглавными с жёлтой подсветкой ключевых слов + подзаголовок.
2. **Проблема / «Знакомо?»**: цитаты-мысли аудитории в карточках, или что изменилось.
3–7. **Пункты / шаги / уроки**: на каждом слайде иллюстрация сверху (SVG/HTML) и текст снизу: тег (жёлтый, капс), заголовок, 1–2 предложения с одной жёлтой подсветкой.
8. **Личное / условие**: факт Константина или «но есть условие: нужна цель».
9. **CTA**: практикум + кнопка «Пишите «ЦЕЛИ» ↓ в комментариях».

Новостная карусель (пример «взлом Binance», 15 слайдов): обложка-иллюстрация с объёмным заголовком → хронология → 10 слайдов-примеров (название, год, сумма крупно жёлтым, что произошло, красный блок «что с деньгами клиентов») → вывод → что делать → CTA.

## 6. Дизайн (фирменный стиль)

- Размер **1080×1350** (4:5). Экспорт PNG, затем JPG качество 93.
- Фон: тёмно-синий градиент **#0E2244 → #081428**, лёгкая сетка 60 px, голубое свечение справа сверху и жёлтое слева снизу.
- Акцент **жёлтый #F5C542**, второй акцент **голубой #6FB7FF**, тревога **красный #FF6B6B**, второстепенный текст **#9AA6B8**.
- Шрифты: **Inter** (ExtraBold 800 для заголовков, SemiBold 600 для текста) и **Lora Italic** (акценты, названия продуктов). Файлы: /usr/share/fonts/opentype/inter/ и /usr/share/fonts/truetype/google-fonts/.
- Размеры: заголовок h1 **72 px** заглавными; текст **44 px**; тег 30 px с разрядкой. Для 40+ не уменьшать текст ниже ~36 px.
- Шапка каждого слайда: слева «@bravo.konstantin», справа «i / N →» (на последнем без стрелки).
- Выделение: `<span class="y">` жёлтая плашка с тёмным текстом. Одна-две подсветки на слайд.
- Иллюстрации делать кодом: карточки, экраны телефона с чатами, графики, шкалы, календарь, монеты, иконки-эмодзи в плашках. Стильно, без фото.
- Объёмный заголовок (обложка новости): многослойный text-shadow (6 слоёв по 2 px вниз, всё темнее) + мягкая тень.
- CTA-слайд: тег «БЕСПЛАТНО · 5 ДНЕЙ», «Практикум» + «Воплощение целей» (Lora italic жёлтым), 5 плиток «день 1…5», строка по теме, жёлтая кнопка «Пишите «ЦЕЛИ» ↓ / в комментариях».

## 7. Фото: правила

- **Только ОДНО личное фото на карусель, на обложке.** Остальные слайды: дизайн и иллюстрации. («Вы сжигаете мои фотографии».)
- Образ: **синий пиджак + очки** (узнаваемый). Без очков не брать.
- **Без фильтров** (фильтр Paris больше не нужен), только лёгкая резкость: UnsharpMask(1.5, 80, 2) — скрипт tools/prep_photo.py.
- Не повторять обложки подряд. Перед выбором посмотреть slide_01 в последних папках репозитория.
- Фото должно подходить по смыслу. Если тема про потерю/кражу, а фото «держится за голову», это выглядит так, будто пострадал Константин. В таких случаях обложка без фото, иллюстрация.
- Фото-база: репозиторий, папка **foto-baza/2026-10-zheneva/** (81 файл), каталог с описаниями и raw-ссылками: README.md в той же папке и документ проекта «фото-база-женева-2026-10».
  - **g*** синий пиджак + очки (использовать), **x*** без очков (не использовать), **s*** семья (редко).
  - Не использовать без нужды кадры с вывесками брендов: **g41 (Rolex), g65 (Montblanc), g68–g70 (Dior)**.
  - По смыслу: время g38, g51, g62–g64 (цветочные часы, горизонтальные); проблема/усталость g59; размышление g49, g50, g53, g58, g71; успех g67; телефон/ИИ g65 (вывеска), g66; лучшие для обложек g27, g39, g42, g46, g72–g76.

## 8. Как сверстать (технически)

Окружение: облачный Linux, Python, Playwright с Chromium установлен (`chromium.launch()` без опций, не переустанавливать). GitHub доступен через git; raw.githubusercontent.com из shell не открывается (это нормально, Metricool его открывает).

```
# 1. Подключить и клонировать репозиторий (в Claude Code: add_repo owner=costa0001 repo=chernoviki-karuseli access=push)
git clone --depth 1 https://github.com/costa0001/chernoviki-karuseli
cd chernoviki-karuseli
# 2. Фото на обложку
python3 tools/prep_photo.py foto-baza/2026-10-zheneva/g58_park_ruka-u-podborodka_dumaet.jpg sharp/cover.jpg
# 3. Скрипт карусели (по образцу tools/example_anti_kontent.py)
PYTHONPATH=tools python3 my_carousel.py      # создаёт out/slide_NN.png и out/sheet.png
# 4. JPG в папку репозитория
python3 tools/to_jpg.py out 2026-11-06-tema-celi
```

Модуль **tools/gendesign.py** даёт:

- `S(i, N, inner, last=False)` — обёртка слайда (фон, сетка, шапка).
- `cover(img, pos, title, sub, N)` — обложка: фото сверху 760 px, заголовок и подзаголовок снизу. `pos` — object-position, например 'center 28%'.
- `cta(i, N, line, word='ЦЕЛИ', tag='бесплатно · 5 дней', title='Практикум', product='«Воплощение целей»', days_tiles=True)` — финальный слайд.
- `render(sl, OUT)` — рендер словаря {номер: html} в PNG + контакт-лист sheet.png.
- Классы: `.txt` (текстовый блок, позиционировать top:…), `.tag`, `h1`, `.p`, `.y` (жёлтая подсветка), `.it` (Lora italic жёлтым). Константы: `Y`, `NV`, `SKY`, `SH` (папка sharp/).

Шаблон текстового блока слайда:

```
sl[3]=S(3,N,f'''<svg ...иллюстрация... style="position:absolute;top:120px;left:0"></svg>
<div class="txt" style="top:700px"><div class="tag">шаг 1</div><h1>Заголовок слайда</h1>
<div class="p">Пояснение. <span class="y">Ключевая мысль.</span></div></div>''')
```

Иллюстрация обычно занимает зону 120–680 px, текст начинается с 640–780 px. Если текст длинный, поднять top.

## 9. Проверка перед публикацией

Открыть sheet.png (контакт-лист) и проверить:

- текст не обрезан и не налезает на иллюстрацию или нижний край;
- нет длинных тире, «вы» везде, валюта верная;
- кодовое слово на CTA правильное, дата старта не указана;
- одно фото на обложке, образ «синий пиджак + очки», без вывесок;
- факты только из разрешённого списка, новости с проверкой;
- номера слайдов 1/N … N/N.

## 12. Публикация через Metricool

- Бренд: **BRAVO Kosta - Business Mentor**, **blogId 5124907**, Instagram bravo.konstantin, timezone бренда **Europe/Kyiv**.
- Инструмент: `createScheduledPost(blogId, date, info)`. Поле **date обязательно** (ISO с +02:00 для Киева), плюс publicationDate внутри info.
- Шаблон info для карусели:

```
{"autoPublish": true, "descendants": [], "draft": false, "firstCommentText": "",
 "hasNotReadNotes": false, "mediaAltText": [], "shortener": false,
 "smartLinkData": {"ids": []}, "providers": [{"network": "instagram"}],
 "media": ["https://raw.githubusercontent.com/costa0001/chernoviki-karuseli/main/<папка>/slide_01.jpg", "..."],
 "publicationDate": {"dateTime": "2026-11-06T12:30:00", "timezone": "Europe/Kyiv"},
 "text": "<подпись>",
 "instagramData": {"type": "POST", "showReelOnFeed": true, "isAiGenerated": false}}
```

- Типы Instagram: **POST** (карусель/фото), **STORY**, **REEL**, **TRIAL_REEL** (пробные рилс, только видео).
- Расписание каруселей: **11:30 и 17:30 по Берлину** (12:30 и 18:30 Киев). Срочные новости ставить сразу (минимум через 2–3 минуты от текущего времени, в прошлое нельзя). Не ставить в одну минуту с другим Instagram-постом.
- Уже стоящие рилс (не трогать): обычно 9:40, 14:10, 18:40 по Киеву + YouTube shorts.
- Перенос / замена: `getScheduledPosts` → `updateScheduledPost(id, uuid, info)`. В update передавать **весь пост целиком** (текст, все media, publicationDate). После update **id меняется**, uuid остаётся. Media уже загруженного поста можно передавать ссылками static.metricool.com из ответа getScheduledPosts.
- getScheduledPosts на большой период даёт слишком большой ответ: запрашивать по 3–4 дня, а если ответ сохранился в файл, разбирать через Python.
- Metricool копирует картинки к себе при планировании, поэтому после публикации файлы в репозитории можно удалять (но лучше хранить как архив).
- Проверка дня: «карусель» = instagram, тип POST, 5+ картинок.

## 14. Ежедневная автоматическая задача

- Название: **«Ежедневные карусели ЦЕЛИ»**, id `trig_01HirGxfgEY99Cory7MNKTbT`, запуск ежедневно **9:52 по Берлину**, режим без подтверждений, уведомление пушем.
- Логика: держать **запас каруселей на 3 дня**. Каждый запуск находит ближайший день, где на 11:30/17:30 меньше 2 каруселей, и делает недостающие (2 шт.) по смыслам 2 вирусных каруселей других авторов. Если всё заполнено на 7 дней вперёд, ничего не делает.
- Кодовое слово берёт из KODOVOE_SLOVO.md (сейчас ЦЕЛИ, без даты старта).

- Изменить задачу можно через `update_trigger` (текст полностью заменяется), посмотреть через `list_triggers`.
